### 2. 两个模块完全独立 (从代码角度)

```
产品价格 (你)                          购物车数量 (他)
└─ ProductService                    └─ ShoppingCartService
   ├─ createProduct()                   ├─ addItem()
   ├─ updatePrice()                     ├─ updateQuantity()
   └─ validatePrice()                   └─ validateQuantity()
        ↓                                    ↓
   PRODUCT 表                         SHOPPING_CART_ITEM 表
   └─ price 列                        └─ quantity 列

关系: 单向的，只读的
  他的代码会读你的 PRODUCT.price
  但绝对不会修改你的数据
```

---

### 3. API端点完全分离

```
你的API (后台 - 商家权限)              他的API (前台 - 顾客权限)
POST /api/v1/private/product         POST /api/v1/cart
PUT /api/v1/private/product/{id}     PUT /api/v1/cart/{cartId}/product/{id}
GET /api/v1/private/product/{id}     POST /api/v1/order
                                     GET /api/v1/cart

→ 没有重叠，没有冲突
```

---

### 4. 唯一的集成点：订单中的价格

```
场景: 购物车结账生成订单
  1. 他读取购物车中的产品
  2. 对每个产品获取价格 (来自你的 PRODUCT 表)
  3. 使用他的数量 × 你的价格 = 小计
  4. 计算订单总价

分工:
  你的责任: 确保 PRODUCT.price 是有效的 (已通过你的测试)
  他的责任: 确保 quantity 是有效的,总价计算正确
  
结果: 没有冲突! 互相补充!
```

## ⚠️ 需要注意的细节

### 1. 数据初始化

```
你的测试:
  @BeforeEach
  public void setUp() {
    // 创建一个价格为29.99的产品
    product = createProduct(price = new BigDecimal("29.99"));
  }

他的测试:
  @BeforeEach
  public void setUp() {
    // 从你创建的产品中读取价格
    // 不能修改产品的价格!
    product = getProduct(); // 读取你创建的
    cart.addItem(product, quantity = 5);
  }
```

### 2. 事务隔离

```
使用 @Transactional 确保每个测试独立:

@Test
@Transactional
public void testPrice() {
  // 测试你的价格逻辑
  // 测试结束后自动回滚
}

@Test
@Transactional
public void testQuantity() {
  // 测试他的数量逻辑
  // 测试结束后自动回滚
  // 不会影响下一个测试
}
```

### 3. 明确的分工界线

```
文档中标注:

【你负责】
✅ ProductService.validatePrice()
✅ 产品创建/修改时的价格验证
✅ 确保数据库中的价格总是有效的

【他负责】
✅ ShoppingCartService.validateQuantity()
✅ 购物车中的数量验证
✅ 订单创建时的总价计算 (price × quantity)

【共同关注】
⚠️ 订单中的价格来自 PRODUCT 表 (你的)
⚠️ 订单中的数量来自 SHOPPING_CART_ITEM 表 (他的)
⚠️ 两者都正确才能生成正确的订单
```
