## 💡 几个关键的"为什么"

### 为什么要有限状态机?

作业要求你选择一个"非平凡的功能模型",FSM最合适因为:

```
✅ 非平凡性:
   - 不是简单的输入输出
   - 有多个状态和复杂的转换逻辑
   - 涉及多个字段的约束条件(特别是价格!)

✅ 与价格相关:
   - DRAFT → PENDING 的转换需要验证价格
   - 这与你现有的价格分区测试完美结合

✅ 容易测试:
   - 每个状态转换可以对应一个测试用例
   - 每个守卫条件可以对应多个测试用例
   - 总共31+个测试,完美覆盖35%的工作量
```

### 为什么要与朋友分工?

```
✅ 工作量合理:
   - 你: 产品价格 + FSM设计
   - 他: 购物车/订单 + FSM设计
   - 各自独立,但相互补充

✅ 冲突最小:
   - 交界点只有"订单价格验证"
   - 可以通过明确的分工界线解决

✅ 学习价值:
   - 你深入理解产品管理
   - 他深入理解购物流程
   - 都能学到不同的东西
```
